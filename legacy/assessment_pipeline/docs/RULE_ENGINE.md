# Rule Evaluation Engine
# Version 2 Specification

## Overview

The Rule Evaluation Engine is the core assessment component of the ARTS Defibrillation Assessment Pipeline.

Unlike the video and audio modules, the Rule Engine performs no detection.

Its sole responsibility is to evaluate timestamped events against predefined clinical assessment rules.

Each rule is deterministic and independently evaluated.

---

# Input

The Rule Engine accepts a unified chronological timeline generated by the Timeline Fusion Engine.

Input:

```python
list[Event]
```

Each event contains:

- event_name
- timestamp
- source
- confidence
- evidence_type
- raw_data

---

# Output

Each rule returns one CriterionEvaluation object.

```python
CriterionEvaluation(
    criterion_id,
    result,
    evidence_type,
    supporting_events,
    failure_reason,
    feedback_message,
    timestamps
)
```

---

# Evaluation Pipeline

Every rule follows the same evaluation sequence.

```
Receive Timeline
        │
        ▼
Check Presence
        │
        ▼
Check Dependencies
        │
        ▼
Check Order
        │
        ▼
Check Timing
        │
        ▼
Apply Inference
        │
        ▼
Evaluate Safety
        │
        ▼
Return CriterionEvaluation
```

---

# Rule Results

Each rule returns exactly one result.

## PASS_DIRECT

Direct evidence observed.

---

## PASS_INFERRED

Direct evidence unavailable.

Assessment completed using approved inference.

---

## FAIL

Criterion violated.

---

## UNABLE_TO_ASSESS

Insufficient evidence.

---

## MANUAL_REVIEW

Evidence exists but cannot be automatically resolved.

---

## CRITICAL_ERROR

Unsafe procedural error detected.

---

# Rule Processing Order

The Rule Engine evaluates criteria using the following sequence.

1. Presence
2. Dependencies
3. Order
4. Timing
5. Inference
6. Safety
7. Feedback generation

---

# Timing Rules

## R7

Evaluate the time between:

- shock_delivered
- start_chest_compressions

Clinical threshold:

- Chest compressions should restart within 2 seconds after shock delivery.

---

## R8

Evaluate the time between:

- stop_chest_compressions
- shock_delivered

Clinical threshold:

- Shock should be delivered within 5 seconds after compressions stop.

---

# Inference Rules

## R9

Inference is applied only when direct evidence is unavailable.

Approved downstream evidence may upgrade a criterion from:

FAIL

to

PASS_INFERRED

Inference rules are deterministic and predefined.

No probabilistic reasoning is performed.

---

# Design Principles

The Rule Engine shall:

- remain deterministic
- produce reproducible results
- separate detection from assessment
- support future rule additions
- remain independent of AI models
- provide explainable assessment outcomes
